# CLARSLIB v3

CLARSLIB - потоковый архиватор с блочным сжатием LZ77 и rANS.
По запросу каждый блок защищается кодом Reed-Solomon.

Этот файл является основной спецификацией формата `CLARSv03`.

## 1. Возможности

- Несколько файлов и каталогов в одном архиве.
- Пустые файлы и каталоги.
- Независимое включение LZ77, rANS и защиты Reed-Solomon.
- Параллельная обработка блоков с сохранением исходного порядка.
- Восстановление до двух поврежденных RS-фрагментов в каждом RS-слове.
- Отказ от перезаписи существующего архива и каталога назначения.
- Удаление незавершенного результата при ошибке.

## 2. Сборка и команды

```sh
cargo build --release
cargo test --test all
cargo test --release --test bench
```

```sh
# Создать archive.mrx из file.txt и directory.
arch create archive file.txt directory

# Создать защищенный архив четырьмя потоками.
arch create --protect --threads 4 archive file.txt directory

# Отключить один или оба этапа сжатия.
arch create --no-lz77 archive file.txt
arch create --no-rans archive file.txt
arch create --no-lz77 --no-rans archive file.txt

# Просмотреть и проверить архив.
arch info archive.mrx

# Извлечь архив в новый каталог output.
arch extract archive.mrx output
```

По умолчанию LZ77 и rANS включены, а Reed-Solomon выключен. Параметр
`--threads N` принимается командами `create`, `info` и `extract`, где `N` от 1
до 64. Если расширение архива не указано, добавляется `.mrx`; другое расширение
считается ошибкой.

## 3. Общая схема

### 3.1 Создание архива

```text
Файлы и каталоги
        |
        v
Проверка имен, типов и ссылок
        |
        v
Поток записей файловой системы
        |
        v
Разбиение на блоки до 65536 байт
        |
        +-------------------------------+
        | Для каждого блока             |
        |                               |
        | LZ77, если включен            |
        |        |                      |
        |        v                      |
        | rANS, если включен            |
        |        |                      |
        |        v                      |
        | Выбор меньшего представления  |
        |        |                      |
        |        v                      |
        | Заголовок блока и данные      |
        | отдельно проходят RS          |
        | при включенной защите         |
        +-------------------------------+
        |
        v
Архив CLARSv03
```

### 3.2 Извлечение архива

```text
Три копии общего заголовка
        |
        v
Побайтовое голосование 2 из 3
        |
        v
Флаги LZ77, rANS и RS
        |
        +-------------------------------+
        | Для каждого блока             |
        |                               |
        | Восстановление RS-заголовка   |
        |        |                      |
        |        v                      |
        | Определение размеров          |
        |        |                      |
        |        v                      |
        | Восстановление RS-данных      |
        |        |                      |
        |        v                      |
        | Декодирование rANS            |
        |        |                      |
        |        v                      |
        | Декодирование LZ77            |
        +-------------------------------+
        |
        v
Проверка записей и создание файлов
```

Этапы rANS и LZ77 при чтении выполняются только для сжатого блока и только
если соответствующие флаги включены.

## 4. Обозначения

Во всех следующих разделах используются только обозначения из этой таблицы.

| Обозначение | Значение |
| --- | --- |
| `raw` | Исходные данные одного блока |
| `raw_size` | Размер `raw`, от 1 до 65536 байт |
| `candidate` | Результат включенных этапов сжатия |
| `stored` | Данные, фактически записываемые в блок |
| `stored_size` | Размер `stored`, от 1 до `raw_size` |
| `threads` | Число рабочих потоков |
| `batch_size` | Число блоков в одной параллельной партии |
| `data_shards` | Число информационных RS-фрагментов, равно 10 |
| `parity_shards` | Число проверочных RS-фрагментов, равно 2 |
| `total_shards` | Общее число RS-фрагментов, равно 12 |
| `shard_size` | Размер одного RS-фрагмента в байтах |
| `payload_size` | Размер данных до добавления RS-защиты |
| `rans_size` | Число байтов на входе или выходе rANS |
| `distinct` | Число разных байтов в модели rANS |
| `frequency` | Нормализованная частота байта в rANS |
| `state` | 32-битное состояние rANS |
| `position` | Текущая позиция в блоке LZ77 |
| `distance` | Расстояние до источника совпадения LZ77 |
| `length` | Длина совпадения LZ77 |

## 5. Физический формат архива

Все целые фиксированной ширины записываются в порядке little-endian. Переменные
длины и размеры файлов записываются как unsigned LEB128.

```text
+--------------------------------------+
| Копия 1 общего заголовка, 9 байт     |
+--------------------------------------+
| Копия 2 общего заголовка, 9 байт     |
+--------------------------------------+
| Копия 3 общего заголовка, 9 байт     |
+--------------------------------------+
| Блок 0                               |
+--------------------------------------+
| Блок 1                               |
+--------------------------------------+
| ...                                  |
+--------------------------------------+
```

### 5.1 Общий заголовок

Логический заголовок имеет размер 9 байт и всегда записывается три раза.
Физический размер равен 27 байтам.

| Смещение | Размер | Поле |
| ---: | ---: | --- |
| 0 | 8 | ASCII-сигнатура `CLARSv03` |
| 8 | 1 | Флаги кодирования |

| Бит | Маска | Значение |
| ---: | ---: | --- |
| 0 | `0x01` | Включен LZ77 |
| 1 | `0x02` | Включен rANS |
| 2 | `0x04` | Включен Reed-Solomon |

Биты 3-7 должны быть равны нулю. Неизвестные биты считаются ошибкой формата.

### 5.2 Блок без RS

```text
+--------------------------+
| raw_size - 1, 2 байта    |
+--------------------------+
| stored_size - 1, 2 байта |
+--------------------------+
| stored, stored_size байт |
+--------------------------+
```

Размеры хранятся со смещением минус один. Поэтому двух байтов достаточно для
значений от 1 до 65536. Блок считается сжатым только при
`stored_size < raw_size`. Отдельный флаг сжатия не нужен.

### 5.3 Блок с RS

```text
+--------------------------------------+
| RS-слово заголовка блока, 60 байт    |
+--------------------------------------+
| RS-слово данных переменного размера  |
+--------------------------------------+
```

Заголовок и данные защищаются отдельно. Сначала читатель восстанавливает
фиксированное RS-слово заголовка и узнает `stored_size`. После этого он может
вычислить и прочитать длину RS-слова данных. Одно объединенное RS-слово
потребовало бы еще одного внешнего поля длины.

### 5.4 Устройство одного RS-слова

Перед кодированием к данным добавляется четырехбайтовый исходный размер.

```text
protected_size = payload_size + 4
shard_size = ceil(protected_size / 10), но не меньше 1
encoded_size = 12 * 4 + 12 * shard_size
```

```text
+--------------------------------------+
| 12 CRC32, по 4 байта                 | 48 байт
+--------------------------------------+
| 10 информационных фрагментов         | 10 * shard_size
+--------------------------------------+
| 2 проверочных фрагмента              | 2 * shard_size
+--------------------------------------+
```

Для четырехбайтового заголовка блока:

```text
protected_size = 4 + 4 = 8
shard_size = 1
encoded_size = 48 + 12 = 60 байт
```

## 6. Логический поток файлов

Перед блочным кодированием файлы и каталоги превращаются в один поток.

```text
Запись файла:
  0x01 | path_length | path | file_size | file_data

Запись каталога:
  0x02 | path_length | path

Конец архива:
  0x00
```

`path_length` и `file_size` записываются как unsigned LEB128.
Каталог всегда записывается раньше его дочерних записей.

## 7. Unsigned LEB128

В каждом байте используются 7 младших битов данных. Старший бит равен единице,
если число продолжается в следующем байте.

```text
Число 127:  0x7F
Число 128:  0x80 0x01
Число 4096: 0x80 0x20
```

Для `u64` допускается не более 10 байтов. В десятом байте допустим только один
значащий бит. Неканонические записи с лишним нулевым байтом отклоняются.

## 8. LZ77

### 8.1 Формат

```text
original_size | команды

Команда без ссылки:
  0x00 | literal

Команда со ссылкой:
  length | distance | literal
```

`original_size` и `distance` записываются как unsigned LEB128. `length` и
`literal` занимают по одному байту.

### 8.2 Кодирование

```text
Текущая позиция
        |
        v
Поиск совпадений в предыдущих 4096 байтах
        |
        v
Выбор самого длинного совпадения
        |
        v
При равной длине выбор ближайшего совпадения
        |
        v
Запись length, distance и следующего literal
```

Последний байт всегда записывается как `literal`. Поэтому совпадение не может
занять весь оставшийся хвост. Декодирование ссылки выполняется по одному байту,
что позволяет копировать перекрывающиеся последовательности.

## 9. rANS

### 9.1 Формат

```text
rans_size
distinct - 1
алфавит или карта из 32 байтов
частоты первых distinct - 1 символов
state, 4 байта
байты перенормировки
```

Последняя частота не записывается. Она вычисляется как остаток до `TOTAL=4096`.

### 9.2 Процесс

```text
Подсчет байтов
        |
        v
Нормализация суммы частот до 4096
        |
        v
Кодирование справа налево
        |
        v
Вынос младших байтов при росте state
        |
        v
Запись модели, state и вынесенных байтов
```

Декодер идет слева направо. Когда `state` становится меньше `LOWER_BOUND`,
он возвращает в состояние очередной байт потока перенормировки.

## 10. Reed-Solomon и CRC32

```text
payload
   |
   v
Добавление четырехбайтовой длины
   |
   v
Разбиение на 10 равных фрагментов
   |
   v
Вычисление 2 проверочных фрагментов
   |
   v
CRC32 для каждого из 12 фрагментов
```

При чтении CRC32 определяет поврежденные фрагменты. Такие фрагменты передаются
Reed-Solomon как отсутствующие. Два проверочных фрагмента позволяют восстановить
любые два обнаруженных поврежденных фрагмента одного RS-слова.

CRC32 не является криптографической защитой и допускает коллизии. Формат не
защищает данные от намеренной подмены и не выполняет шифрование.

## 11. Троирование общего заголовка

```text
Копия A ----+
            |
Копия B ----+--> Голосование каждого байта --> Заголовок
            |
Копия C ----+
```

Для каждой позиции:

```text
если A == B или A == C: результат A
иначе если B == C:      результат B
иначе:                  ошибка
```

Троирование исправляет одну ошибочную копию каждого байта. Оно не обнаруживает
случай, когда две копии одинаково повреждены.

## 12. Параллельная обработка

```text
Входные блоки:   [0] [1] [2] [3] [4] [5]
                      | партия |
Рабочие потоки:       0  1  2  3
                      | |  |  |
Результаты:      [0] [1] [2] [3] [4] [5]
```

Rayon обрабатывает блоки партии параллельно, но собирает результаты в исходном
порядке. Поэтому число потоков не меняет байтовое представление архива.

Для одного потока размер партии равен одному блоку. Для нескольких потоков:

```text
batch_size = max(4, 2 * threads)
```

Два задания на поток уменьшают простой при разном времени сжатия блоков.
Минимум четыре задания сохраняет полезный параллелизм при двух потоках.

## 13. Проверка путей и откат

```text
Имя записи
   |
   v
Проверка UTF-8, длины и компонентов
   |
   v
Проверка родительского каталога
   |
   v
Проверка дубликата без учета регистра
   |
   v
Создание файла или каталога
```

Архив создается только как новый файл. Каталог извлечения также должен быть
новым. При ошибке незавершенный архив или каталог извлечения удаляется.

Символические ссылки и Windows reparse points не архивируются. Архив, созданный
внутри исходного каталога, исключается из входных данных.

## 14. Константы и обоснование

### 14.1 Формат и блоки

| Константа | Значение | Причина |
| --- | ---: | --- |
| `BLOCK_SIZE` | 65536 | Максимум, представимый полем `raw_size - 1` типа `u16` |
| `ARCHIVE_HEADER_SIZE` | 9 | 8 байтов сигнатуры и 1 байт флагов |
| `BLOCK_HEADER_SIZE` | 4 | Два поля `u16`: `raw_size - 1` и `stored_size - 1` |
| Число копий общего заголовка | 3 | Минимум для голосования большинством и исправления одной копии |
| `MAX_THREADS` | 64 | Ограничивает случайное создание слишком большого пула; не является требованием формата |

### 14.2 LZ77

| Константа | Значение | Причина |
| --- | ---: | --- |
| `WINDOW` | 4096 | Ограничивает память и время поиска; расстояние до 4096 занимает не более 2 байтов LEB128 |
| `MAX_MATCH` | 255 | Длина команды хранится в одном байте |
| `HASH_BITS` | 12 | Создает 4096 корзин, столько же, сколько позиций в окне |
| `HASH_SIZE` | 4096 | Равно `1 << HASH_BITS` |
| `NONE` | `usize::MAX` | Служебное значение, которое не может быть допустимым индексом позиции блока |
| `MAX_CANDIDATES` | 512 | Равно одной восьмой окна и является степенью двойки; ограничивает один поиск величиной `512 * 255 = 130560` сравнений байтов, но сохраняет 512 последних кандидатов |
| Множитель хеша | `0x9E3779B1` | Мультипликативное смешивание распределяет 16-битные пары по старшим 12 битам |
| `MAX_ENCODED_SIZE` | `3 + 2 * BLOCK_SIZE` | До 3 байтов длины и худший случай из пары `0, literal` на каждый входной байт |

### 14.3 rANS

| Константа | Значение | Причина |
| --- | ---: | --- |
| `SCALE_BITS` | 12 | Таблица из 4096 элементов мала и дает достаточную точность частот |
| `TOTAL` | 4096 | Равно `1 << SCALE_BITS`; сумма всех частот |
| `LOWER_BOUND` | 8388608 | Равно `1 << 23`; оставляет 8 бит для байтовой перенормировки в `u32` |
| Верхняя граница `state` | 2147483648 | Равно `LOWER_BOUND * 256`; значение остается внутри `u32` |
| Порог списка алфавита | 32 | Список до 32 байтов не длиннее фиксированной карты из 32 байтов |
| `MIN_HEADER_SIZE` | 7 | 1 байт длины, 1 байт числа символов, 1 символ и 4 байта состояния |
| `MAX_HEADER_SIZE` | 550 | 3 байта длины, 1 байт числа символов, карта 32 байта, 255 частот по 2 байта и состояние 4 байта |

### 14.4 Reed-Solomon и CRC32

| Константа | Значение | Причина |
| --- | ---: | --- |
| `DATA_SHARDS` | 10 | Совместно с двумя parity-фрагментами создает 20 процентов избыточности |
| `PARITY_SHARDS` | 2 | Позволяет восстановить любые два обнаруженных поврежденных фрагмента |
| `TOTAL_SHARDS` | 12 | Сумма 10 информационных и 2 проверочных фрагментов |
| Размер CRC32 | 4 байта | CRC32 возвращает 32-битное значение |
| Внутренний размер | 4 байта | `u32` покрывает все допустимые размеры блока и промежуточного потока |

### 14.5 Пути и ограничения ресурсов

| Константа | Значение | Причина |
| --- | ---: | --- |
| `MAX_PATH_BYTES` | 4096 | Явный предел памяти и распространенный системный предел полного пути |
| `MAX_DEPTH` | 128 | Ограничивает вложенность и глубину рекурсивного обхода |
| Максимум компонента | 255 байт | Совместимо с распространенным пределом файловых систем |
| `MAX_ENTRIES` | 100000 | Ограничивает память множеств имен и время обработки недоверенного архива |
| Windows reparse mask | `0x400` | Системный атрибут Windows `FILE_ATTRIBUTE_REPARSE_POINT` |

Значения `MAX_THREADS`, `MAX_DEPTH` и `MAX_ENTRIES` являются политикой ограничения
ресурсов. Они не влияют на математическую корректность формата.

## 15. Инварианты и ошибки

Читатель отклоняет архив, если выполняется хотя бы одно условие:

- После побайтового голосования нет большинства или получена неверная сигнатура.
- Установлены неизвестные флаги.
- `stored_size` больше `raw_size`.
- Сжатый блок объявлен при выключенных LZ77 и rANS.
- CRC32 не совпадает более чем у двух фрагментов одного RS-слова.
- После декодирования получен размер, отличный от `raw_size`.
- Varint переполнен, оборван или записан неканонически.
- Путь пуст, слишком длинен, повторяется или ссылается на необъявленный каталог.
- После маркера конца архива остались данные.

## 16. Тестирование

Основной набор запускается командой:

```sh
cargo test --test all
```

Он проверяет:

- LZ77 на примере `ABABABA`, строке с повторениями и граничных размерах.
- rANS на строке `БАНАН`, псевдослучайных данных, пустом входе и всех 256 значениях байта.
- Reed-Solomon при повреждении одного, двух и трех фрагментов: первые два случая восстанавливаются, третий отклоняется.
- Троирование при повреждении одной копии, разных мест двух копий и одного байта всех трех копий.
- Создание, просмотр и извлечение обычного и защищенного архива `demo_corpus` с полным сравнением файлов.

Набор содержит 13 демонстрационных проверок. Он показывает основные успешные
сценарии и границы защиты, но не ставит целью покрыть каждую ветвь кода.

## 17. Бенчмарк

Для корректных измерений бенчмарк запускается в release-сборке:

```sh
cargo test --release --test bench
```

Он содержит пять разделов:

- Общая скорость упаковки и распаковки вместе со степенью сжатия.
- Отдельная скорость LZ77, rANS и последовательности LZ77 + rANS.
- Масштабирование упаковки на 1, 2 и 4 потоках.
- Изменение размера и времени при включении Reed-Solomon.
- Однократное создание и извлечение реального корпуса `demo_corpus` с проверкой всех файлов.

Внутренние измерения используют повторяющийся текст, псевдослучайные данные и
смешанные блоки. По умолчанию размер каждого набора равен 1 МиБ, выполняются
один прогрев и пять измерений, после чего выбирается медиана. Эти параметры
можно изменить переменными окружения:

```text
CLARSLIB_BENCH_BYTES=<размер в байтах>
CLARSLIB_BENCH_RUNS=<число измерений>
```

Полный `demo_corpus` обрабатывается один раз и не зависит от этих переменных.
Бенчмарк измеряет производительность, а корректность алгоритмов проверяет
`tests/all.rs`.

Перед выпуском выполняются:

```sh
cargo fmt --all -- --check
cargo clippy --lib --bin arch --test all --test bench -- -D warnings
cargo test --test all
cargo test --release --test bench
```

## 18. Ограничения защиты

- Reed-Solomon исправляет только обнаруженные стирания, а не произвольные ошибки.
- CRC32 может иметь коллизии и не является средством аутентификации.
- Таблица CRC32 находится вне RS-данных.
- Троирование не помогает, если две копии одного байта одинаково повреждены.
- Формат не шифрует имена и содержимое файлов.
- Архивы `CLARSv02` несовместимы с `CLARSv03`.
